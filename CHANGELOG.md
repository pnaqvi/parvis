# Parvis CHANGELOG

The system release is X.Y, recorded in this file and in VERSION. Skills carry X.Y.Z, where Z moves on a skill edit and X.Y re-baselines at a release.

## Release 2.3 (2026-09-19)
- Parvis is now a system anyone can adopt. Clone the repository, fill in one file and run it. No skill, document or seed file names a person, an employer or an org. Identity, org, scale, industry and preferences come only from the owner skill, and live operational facts from `portfolio-planning/org-context.md` in memory.
- The identity skill `user` becomes `parvis-owner`, invoked as `/parvis-owner`. Its template form carries the `<!-- parvis:owner-template -->` marker on its first line, which is how the installer tells an unfilled copy from a filled one. This release ships the file filled in with the maintainer's profile rather than the blank template, so a new owner replaces its contents after cloning. Either form holds the same sections, which are profile, org, domain and industry (regulators, frameworks, risk rating scale), signature accomplishments, positioning, credentials and visibility, communication preferences and optional sensitive context, each with one line of guidance. The filled-in copy lives only at `~/.claude/skills/parvis-owner/SKILL.md`. The installer copies the template only when no owner skill is installed or the installed one still carries the marker, adopts a filled-in `user` skill into `parvis-owner`, backs up a filled-in profile to `~/.claude/parvis-retired-profile-backup.md` before retiring the skill that holds it, and reports what it kept. Name-based marker detection is gone, though the older `user-template` marker is still recognised.
- Every other skill is now `parvis-*` (parvis-core, parvis-memory, parvis-exec-writer, parvis-incident-command, parvis-infra-advisor, parvis-meeting-prep, parvis-metrics-advisor, parvis-people-leader, parvis-portfolio-planning, parvis-research, parvis-reviews, parvis-risk-regulatory, parvis-stakeholders, parvis-vendor-eval). `parvis` and `be-human` keep their names. The roster is still seventeen.
- The two homes are renamed `parvis-memory` and `parvis-workspace`. Rename pre-2.3 homes to those names by hand before re-running the installer, because homes are no longer detected by their old names.
- The home location is a per-machine setting. The base defaults to `~/ai_working_Directory`, `PARVIS_BASE` on the first install chooses another, and the receipt remembers it. `install.sh --relocate` moves existing homes after checking they are clean git repositories, the destinations are empty and the move is a rename on one volume, verifies each HEAD afterwards and moves back on failure.
- Skills, seeds and help documents no longer hard-code the home paths. They name the memory home and the workspace home, whose paths the managed block states, and parvis-memory's two-homes section is the single source. The install guide gains "Choosing where the homes live" and "Moving the homes later".
- Org groups are created at initialization instead of being seeded. The four group sections the seed used to carry are gone, and step 6 creates one section per org group named in the owner skill and fact sheet, from the group template, through parvis-memory's "create a memory section". `enterprise-architecture` stays seeded as a functional section for anchor decisions, reference architectures, standards and current posture, without its group framing. The seed now holds thirteen sections.
- Initialization. Step 3 becomes "Build or confirm the owner skill", drafted from a resume or LinkedIn export in the new seed-pack bucket "You". Step 12 first collects the org's risk frameworks, regulators and rating scale and re-confirms the clearance for regulatory material. The definition of done gains a line for the owner skill and one for the frameworks and scale.
- The Prime Directive now reads "Make the user better at everything they choose to do, and never let them walk into something blind." `/parvis` greets the user by the name in the owner skill.
- The punctuation rule moves to the owner skill. be-human applies the punctuation preferences stated there, and defaults to no em dashes and rare colons and semicolons when none are stated.
- parvis-risk-regulatory is written for regulated organizations in general, with frameworks as examples to confirm at initialization. The technology-leadership skills (infra-advisor, metrics-advisor, research, the platform program doctrine) are described as applying when the owner skill names technology as the domain.
- Installer. The roster uses the new names including `parvis-owner`. The managed block (v2.3) names no one, and the fallback git identity is "Parvis User" at user@parvis.local. Legacy infra-platform homes are still detected and reported, never migrated, and the install guide gives the by-hand steps for anyone who wants that data moved.
- Removed build history and redundant references from the repository.
- The README describes Parvis as a system anyone can adopt and adds a "Make it yours" section. The six help documents are rewritten to address the reader, and their docs/ mirrors are refreshed.
- T6 re-measured with wc -w at 31,410 words in the seventeen SKILL.md files and 38,285 in the references, which is 2,089 fewer reference words than 2.2 after the cleanup pass.
- All skills re-baselined to 2.3.0.

## Release 2.2 (2026-09-19)
- New skill parvis-risk-regulatory, the seventeenth. It is the user's lens on everything examiners, internal audit and the second line inspect. An issues ledger mirrors regulator, audit, second-line, external and self-identified findings by ID from open to validated closure, with immutable baseline dates. A risk register holds operational, technology, cyber, third-party, data, AI and change risk, and every acceptance must carry an approver and an expiry. Beside them sit the exam and audit calendar and the AI agent inventory with each control marked evidenced, asserted or absent. Its modes are log and update, the risk pulse, exam and audit prep, remediation review, risk assessment and acceptance, cyber risk, AI governance and upward reporting, with five panel lenses (examiner, internal auditor, second-line risk officer, adversary, board risk committee member). Schemas, signals and procedures live in its references/risk-craft.md.
- Three rules come first in it. The org's GRC record stays authoritative and Parvis mirrors it. Confidential supervisory information never enters, so findings are held by ID and the user's own paraphrase. Cyber risk is held at the altitude of controls, never of exposures.
- New confidential memory section risk-regulatory (sync no, a nested local-only repository), making seventeen sections and four confidential ones. New workspace folder risk/.
- The installer now adds a section a release introduces to an existing memory home, copying it whole from the seed and inserting its manifest row, and changes nothing already present. An ignore line added for a confidential section is now committed on its own, so an upgraded home is left clean. The roster is seventeen names and the confidential list is four.
- The memory pulse gains check 8, risk and regulatory signals, reported as counts and IDs only. Initialization gains step 12 for risk, audit, regulatory and cyber, a seed-pack bucket for it, and regulatory material in the clearance gate, so there are seventeen steps. parvis-reviews may cite open issue counts and states in an MBR risk section.
- T6 re-measured with wc -w at 30,380 words in the seventeen SKILL.md files and 38,432 in the references. 2.2 added 1,848 and 2,257.
- All skills re-baselined to 2.2.0.

## Release 2.1 (2026-09-19)
- The Prime Directive, making the user better at everything they choose to do and never letting them walk into something blind. It heads parvis-core with seven rules that put it into practice (the user's interests first, truth over comfort, anticipate, remember for them, protect them, they decide, keep it human), and it outranks every tenet and skill. Parvis is framed as the user's trusted companion, the way JARVIS was to Tony Stark, rather than a tool they operate.
- The managed CLAUDE.md block gains one line naming the system Parvis and stating the directive, so it is on in every session, survives context summarisation, and costs about forty tokens. The rules themselves live only in parvis-core, so nothing is maintained twice.
- New skill parvis, the sixteenth. Typing /parvis starts a session. It loads the profile, parvis-core and be-human, reads both manifests, greets the user by name with one interesting thing (a real memory item when there is one, never invented), answers "who are you" in its own voice, and routes every later message to the owning skill. It fires only when typed and carries no rules of its own. The installer roster is sixteen names, and updating from 2.0 installs parvis and replaces the v2.0 managed block with the v2.1 one.
- initialization.md becomes the single home of the sequence, and parvis-memory points to it instead of carrying a second copy. Initialization is document-first. A seed pack of existing documents goes into the new workspace inbox/seed/, every file is screened for T3 content and filed with a manifest row, and each step is drafted from the extracted candidates for the user to confirm. A clearance gate opens every work-machine run and records what employer policy allows, and where that is unclear the run is sanitized-only and the confidential sections stay empty. The order is install, verify, shakedown, initialize, so the machine is proven before real data goes in.
- The installer reads init-status.md and ends with the next step to take, whether initialization is not started, in progress or complete. /parvis offers to start or continue initialization in its greeting until the status is complete.
- Both homes and each confidential section repo ship an LF .gitattributes, so core.autocrlf=true no longer warns on every register write, and the installer adds a missing one to existing homes and commits only that file. T12 has one trigger. Ledger rows are written when an artifact is declared sent, a draft plan writes nothing, and a git commit is never the trigger.
- Point versions 2.1.1 and 2.1.2 carried these changes as they landed. All skills re-baselined to 2.1.0.

## Release 2.0 (2026-09-19)
- The system is renamed Parvis, and its repository with it. The installer writes its receipt and managed block under the new name and still recognises a 1.x block and a 1.x skill header, so a machine on 1.x updates in place.
- Absorbed infra-platform-system, the separate platform-program skill family, into this repository. Two systems for one job meant two installers, two memory homes and two tenet sets covering the same ground, so its twelve skills were merged in and the system is one product again. The roster is now fifteen skills. Three are new, parvis-metrics-advisor, parvis-research and parvis-reviews, because metrics and value, structured research, and the monthly and quarterly review cycle had no existing home. Eight more infra skills merged into their existing counterparts, and infra's comms skill folded into parvis-exec-writer rather than surviving as a near-duplicate writer.
- Two data homes instead of one. The memory home holds curated durable facts and grows from fourteen sections to sixteen with platform-products and metrics-value. The workspace home holds working documents, seeded from the new workspace-seed/ directory with a manifest, dated monthly and quarterly cadence folders, and an indexed reference folder. They stay separate on purpose, because a fact and a draft have different lifecycles.
- Thirteen tenets. T1 to T10 are unchanged. T11 makes the workspace the system of record, T12 puts every promise from a sent artifact into a commitments ledger instead of memory, and T13 requires shareable prose to be scrubbed before it is final.
- The installer is now a lifecycle tool. It detects a fresh install or an update, retires skills a release dropped (including the twelve old infra-platform-* skills), and writes an install receipt so it only ever removes what it installed. It detects legacy infra data homes and reports them, but does not migrate them and leaves them completely untouched. --uninstall removes the skills and the managed CLAUDE.md block and keeps all data, and --uninstall --purge also deletes both homes behind a typed confirmation, and only after checking that each recorded home path is a real Parvis home and not the home directory or anything above it. The confidential memory sections are now kept out of the outer repository on every run, not only on first install, so an older home cannot leak them to a later remote. tools/package-skills.sh builds one .skill bundle per skill into dist/ on demand, and built bundles are never committed.
- All skills re-baselined to 2.0.0.

## Earlier history

Releases 1.0 through 1.3 were published on 2026-08-08 and 1.4 on 2026-09-17. 1.0 was the first versioned release. It consolidated five build iterations and added version headers, a VERSION file, an idempotent install.sh and Apache-2.0 licensing. 1.1 moved the system home under `~/ai_working_Directory/` and added the at-a-glance skills catalog. 1.2 grew stakeholder management into a full capability with parvis-stakeholders and its registry, and raised portfolio work to program oversight with baselined milestones, an early-warning catalog and a recovery playbook. 1.3 made parvis-people-leader first class with person files and talent review, and made the identity profile and be-human always-on through the managed CLAUDE.md block. 1.4 settled the punctuation rule in one wording across be-human, parvis-core, exec-writer and the installer. Word counts recorded before 2.2 were taken by a different count and are not comparable with the figures above.
